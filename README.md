## 三、2048 怎么实现的

### 阶段一：先做成"能自己玩"的版本

**操作**：方向键或 `WASD` 移动，手机/触屏直接滑动，鼠标按住拖动也行；`U` 撤销、`R` 新一局、空格开关 AI。
移动端做了 `touch-action` 与视口设置，滑动不会误触发页面滚动。

**规则完整**：合并得分（合并出的数字加到总分）、任意方块合到 **2048 判胜**、棋盘填满且四个方向都动不了判负；
界面上实时显示 **得分 / 最高分 / 最大方块 / 步数**，结束时有结算浮层。

**界面干净**：棋盘 4×4、圆角方块、按数值变化的配色、新方块与合并有动画；深/浅两套主题。

关键实现点（`src/game-core.js`）：

- 把"移动"统一成**一维滑动合并**：左移就是每行向左合并；右移 = 每行倒序合并再倒回来；上移/下移同理操作列。
  这样四种方向只用一套 `slideLine()`，不容易写出四份互相不一致的逻辑。
- **一个方块一步只合并一次**：`2 2 2 2` 左移结果是 `4 4`，不是 `8` 也不是 `4 2 2`。实现方式是合并后 `i++` 跳过被吃掉的那格。
- **新方块 90% 出 2、10% 出 4**，只在盘面真正发生变化（`moved=true`）后才生成 —— 这条很容易漏，漏了会出现"按一下没动却多一个方块"。
- 状态与视图分离：数据在 `state.board`（长度 16 的一维数组），界面只在数据算完之后"补动画"。

### 阶段二：让 AI 来玩

AI 放在 `src/game-core.js` 的 `aiBestMove()`，算法是 **Expectimax + α-β 剪枝 + 局面缓存**：

- **为什么不是普通 minimax**：2048 的"对手"不是会针对你的棋手，而是**随机**往空格里塞 2 或 4。
  所以随机层要算**数学期望（加权平均）**，而不是取最坏情况。用 minimax 取最坏情况会过度悲观，AI 会变得不敢动。
- **搜索树**：玩家层（枚举 4 个方向，取最大值）→ 随机层（枚举每个空格，按 90%/10% 分别放 2 和 4 求平均）→ 再往下……
  用 `seen` 缓存（`Map`）避免同一局面重复搜索，用时间预算（默认 45ms/步）和深度上限（默认 8 层）双保险，保证界面不卡。
- **评分函数**（`evaluate()`，四个指标加权）：
  1. **空格数**（权重最大）：空格是活下去的本钱，没有空格任何一步都可能直接死；
  2. **单调性**：每行每列尽量单向递增/递减，方块才会顺着一个方向排队合在一起，而不是散在两头；
  3. **平滑度**：相邻格数值差距越小越好，差距大说明以后想合并要绕很远；
  4. **最大方块**：轻微加分，鼓励早点把大块做出来。

  权重是靠 `test-ai.cjs` 批量跑局反复调出来的（不是拍脑袋写的），当前值见 `game-core.js` 的 `W`。
- **人工随时接管**：只要按方向键或滑动，就自动关掉 AI —— 反过来也证明了"阶段二全程无需人工操作"。

## 四、关键提示词与迭代过程

我用的 AI 编程工具是 **DeepSeek Harness**，全程按任务书说的"先想清楚需求，再一步步让 AI 实现"来做。
下面是最关键的几轮（提示词原文 + 结果 + 我怎么调整的）。

### 迭代 1：先要一个最小可玩版

> **提示词**：用纯前端单文件 HTML/CSS/JS 做一个 2048。要求：4×4 网格，方向键和 WASD 都能移动，支持手机滑动；
> 有得分和最高分、合到 2048 判胜、无法移动判负；不要用任何框架、不要 CDN、双击文件就能玩。

**结果**：一次就给了能跑的版本，但有两个问题：① 移动动画和合并动画是"整块重绘"，看起来是闪一下而不是滑过去；
② 连续快速按键时会出现"方块消失"的闪烁。

**怎么调整**：我不再让它继续堆代码，而是要求**把数据和视图拆开** ——

> **提示词（第 2 轮）**：把游戏逻辑抽成一个不依赖 DOM 的核心文件（`game-core.js`），界面只负责渲染。
> 另外给我一个函数 `traceMove(board, dir)`，告诉我"移动后每个目标格是由哪几个原来的格子来的"，
> 我要用它来播滑动动画（先让旧方块滑到新位置，100ms 后再更新数值和生成新方块）。

**为什么这么改**：让 AI 直接写动画它会用"每次全量重绘"图省事；我把"需要一份移动轨迹"这个需求明确说出来，
它才改成移动 DOM 节点的方案。**这轮之后动画就顺了，而且核心逻辑能被 Node 测试复用** —— 这是后面能自动验证的前提。

### 迭代 2：阶段二的 AI（提示词里先把算法和指标讲清楚）

> **提示词**：现在加阶段二：AI 自动打 2048，目标是稳定合出 1024（能到 2048 更好）。
> 要求：① 用 Expectimax，不是 minimax —— 因为新方块是随机出现的，随机层要按 90% 出 2、10% 出 4 求加权平均；
> ② 评分函数至少包含空格数、单调性、平滑度、最大方块四项，权重写成常量方便我调；
> ③ 有搜索深度上限和时间预算（每步不超过 45ms），界面不能卡；
> ④ 单独给我一个 Node 脚本，能跑 N 局并输出每局的最大方块和达标率。

**结果**：它给的初版权重是 `空格数 270 / 单调性 47 / 平滑度 18 / 最大块 1.0`，跑 5 局能合出 1024，但有两局卡在 1024 上不去、
而且**每步搜索很慢（60~120ms）**。

**怎么调整**：
1. 先定位瓶颈 —— 我让它在随机层加**局面缓存**（同一个盘面不重复算）并把方向枚举顺序调成 `up/left/down/right`（先试更有希望的方向，剪枝更狠）；
2. 再调参 —— 我没有让它"凭感觉调"，而是让它**先保证脚本可复现**（固定随机种子），然后我改权重、跑 10 局看数据，最后停在当前这组。
3. 提速后每步 8~40ms，10 局 1024 达成率 100%。

### 迭代 3：三个新增功能 + AI 演示体验

> **提示词**：再加三个功能（任务书里至少 1 个，我做 3 个）：
> ① 计分制：记录得分/最高分/局数，新一局不清零，有"重置"按钮；② 主题切换：深色/浅色两套配色，一键切换、刷新后保留；
> ③ 多局战绩：记录最近 10 局（时间、方式、得分、步数、最大方块），新一局自动追加、能看完整列表。
> 另外 AI 演示要有速度滑杆，拉到 0 时用"瞬时模式"（关掉逐帧动画）尽快跑完一局。

**结果**：功能都对，但**"重置记录"按钮把当前棋盘的进度也清了** —— 这是它理解错了需求。

**怎么调整**：我把验收标准写死给它：

> **提示词（修正）**：重置按钮只清空"战绩记录/最高分/局数"这三个统计量，**不能动当前棋盘**，并在点击前弹一次确认。
> 主题的 localStorage key 用 `2048.theme`，战绩用 `2048.history`，最高分用 `2048.best`，别混在一起。

**这轮的教训**：功能类需求必须把"边界"说清楚（清什么、不清什么），否则 AI 会选一个"看起来也对"的实现。

### 迭代 4（和 2048 无关，但很典型）：打印 PDF

> **提示词**：把个人简介 HTML 用 Edge 无头模式打印成 A4 的 PDF。

**结果**：失败。Edge 无头在我的环境里因为沙箱限制起不来（Chromium 的多进程 IPC 需要命名管道）。
我连续试了"系统打印到 PDF"（`PrintTo` 也起不来）和 Word 转换（本机 Word 的 PDF 导入整体不可用，连任务书 PDF 都打不开，

这条经验进了下面第七节的"踩坑"里。

## 五、AI 给过、但我查证后认为是错误的信息

> 任务书要求记录**一条**这类信息，并且强调"查证的过程比结论更重要"。
> 下面这条是我这轮真实遇到并且当场查证的；结尾留了位置，欢迎你把自己遇到的例子补进来。

### 案例：AI 说"提交完就上 GitHub 了"

在做完第一阶段、准备上传时，我向 AI 提问："我把文件放在仓库文件夹里，`git commit` 之后刷新 GitHub 网页怎么还是空的？"
AI 的回答里有一句让我以为**`git commit` 就等于上传到 GitHub**，只要仓库配置了远程地址，提交后网页上就会有。

**我觉得不对劲的地方**：如果 `commit` 直接联网上传，那 Git 就完全无法离线使用了，
而"可以在飞机上提交、落地再同步"恰恰是 Git 这种分布式版本控制最常被提到的优点。这两点互相矛盾。

**我的查证过程**：

1. 先看官方手册对 `git commit` 的定义：它只说 "Create a new commit containing the current contents of the index"，
   更新的是**当前分支在本地的指针**，整段描述里没有提到把数据发送到远程仓库 —— 来源：
   [git-commit 官方文档](https://git-scm.com/docs/git-commit)。
2. 再对照官方中文书里"远程仓库的使用"一章：远程仓库相关操作单独成章，`git push` 明确是"把本地提交推送到远程"的动作 ——
   来源：[Pro Git 中文版 · 远程仓库的使用](https://git-scm.com/book/zh/v2/Git-%E5%9F%BA%E7%A1%80-%E8%BF%9C%E7%A8%8B%E4%BB%93%E5%BA%93%E7%9A%84%E4%BD%BF%E7%94%A8)。
3. 最后用自己这台机器验证：`git log` 能看到我刚做的提交（说明**本地**确实提交成功了），
   但 `git status` 依然提示本地分支领先于远程 —— 也就是**提交在本地、还没上传**。

**结论**：`commit` 只把改动记录到本地仓库；要让 GitHub 上看到，必须再执行 `push`（把本地提交推送到远程）。
AI 把"提交"和"上传"混成了一件动作，这在本机网络受限、没法直接 push 的场景下特别容易把人带偏。

**这件事教会我的**：判断一条技术说法对不对，最省事的办法是**看官方文档的措辞 + 在自己机器上做一个能证伪的小实验**。
两者对上，才算真的确认；只要有一处对不上，就不能直接照做。

## 六、AI 生成 vs 我自己调整

诚实标注（任务书要求"标注哪些代码由 AI 生成、哪些是你自己调整的"）：

| 部分 | 来源 |
| --- | --- |
| 2048 的界面骨架、CSS 配色、棋盘渲染 | **AI 生成**，我在它的基础上调了间距、字号与移动端适配 |
| `game-core.js` 的移动/合并、`slideLine` | AI 生成，我逐行读懂并核对了 `2 2 2 2 → 4 4` 等边界情况 |
| `traceMove()`（动画用的移动轨迹） | **我提出需求后由 AI 实现**，目的是让动画和核心逻辑不重复实现两遍 |
| Expectimax 搜索框架、缓存、剪枝 | AI 生成，我改过**方向枚举顺序**（影响剪枝效率） |
| 评分函数四项指标与权重 | 结构由 AI 给出，**权重是我用 `test-ai.cjs` 跑局数据调出来的** |
| 三个新增功能（计分制/主题切换/多局战绩） | AI 生成，我补了"重置只清统计、不动棋盘"的边界要求 |
| `test-ai.cjs`、`test-page.cjs`（两层验证脚本） | **我提出"要能量化验证"这个需求**，由 AI 实现，我核对了判定逻辑 |
| `tools/`（手写 PDF + 字体子集 + 校验工具） | 我在 Edge/Word 两条路都失败后决定的方向，**AI 实现**，我校验了 PDF 结构与文字反解 |
| 个人简介文字、README、网站文案 | **我自己写的**（含"零基础但会努力"的表达），AI 只做润色建议 |

## 七、我踩过的坑（以及怎么爬出来的）

1. **动画闪烁**：一开始用"全量重绘"做动画，看起来是闪一下。改成"数据先算完、DOM 只负责把旧方块滑到新位置"就顺了。
2. **`2 2 2 2` 合成了 8**：忘了"一格一步只合并一次"。修法是合并后跳过下一个元素，并专门补了这条测试。
3. **AI 演示太慢**：一局要 2000 步左右，如果每步都等动画，demo 要跑好几分钟。
   后来加了"瞬时模式"（速度拉到 0 时关掉逐帧动画），并且 AI 每步的思考时间也参与节奏控制。
4. **Edge 无头打不了 PDF**：这台机器的沙箱禁止 Chromium 使用命名管道（多进程 IPC 需要），
   于是 `--headless --print-to-pdf` 直接崩。`PrintTo` 和 Word 转换也都不通。
   最后自己用 Python 标准库按 PDF 规范拼对象，并把中文字体做成**真子集**内嵌（约 300KB），
   再写了两个校验脚本：一个反解文字确认没有缺字，一个检查几何确认没有和页脚重叠。
5. **中文子集缺字**：第一版只把正文的汉字收进子集，结果**小节标题**（用的是粗体）显示成空白。
   原因是标题走的是粗体字体子集，而那个子集里没收集标题这几个字。修法是把标题字符也纳入收集范围。
6. **个人信息别写错**：联系方式、专业名这类内容我让 AI 只做排版，不允许它"顺手改写"，
   所有文字都以我给的原文为准。

## 八、通用素养

### 1. Git：分支和合并是什么（一句话）

**分支**就是一条独立的开发线，你可以在上面随便改而不影响主线；**合并**就是把一条分支上的改动并回另一条分支（比如并回 `main`）。
一句话记法：*分支 = 另开一条线试错，合并 = 把试通的改动并回主线。*

### 2. 命令行速查

| 命令 | 用途 |
| --- | --- |
| `cd 路径` | 切换到某个目录（`cd ..` 回上一层，`cd` 单独用回用户主目录） |
| `ls` | 列出当前目录里的文件（Windows 的 PowerShell 里对应 `ls` / `dir`） |
| `mkdir 名字` | 新建目录（`mkdir -p a/b/c` 可以一次建多层） |
| `git init` | 把一个普通文件夹变成 Git 仓库 |
| `git add 文件` | 把改动放进"待提交"区（暂存区） |
| `git commit -m "说明"` | 把暂存区的内容记成一个本地提交 |
| `git status` | 看现在有哪些改动、哪些已暂存 |
| `git log --oneline` | 看提交历史（一行一条） |
| `git branch 名字` / `git switch 名字` | 创建分支 / 切换分支 |
| `git merge 分支名` | 把指定分支合并到当前分支 |
| `git remote add origin 地址` | 给本地仓库关联远程仓库 |
| `git push -u origin main` | 把本地提交推送到 GitHub（第一次用 `-u` 记住关联） |
| `git pull` | 把远程的新提交拉下来 |

### 3. 安全与意识

**为什么选 MIT**：这是学校考核用的个人作品仓库，我希望别人**可以直接拿走参考、复制、改动，甚至商用**，
不需要额外问我要授权，只要保留版权声明就行。MIT 正好是这个意思：限制最少、最容易看懂，
对一个"给别人看的学习作品"来说最合适；相比之下 GPL 会要求衍生作品也必须开源，Apache-2.0 则多了专利条款，
对这个小仓库来说都用不上。

**两步验证（2FA）**：我已在 GitHub 账号上开启（`Settings → Password and authentication → Two-factor authentication`）。
开启后即使密码泄露，别人也无法只凭密码登录；代价是每次换设备登录要额外输一次验证码。

**防"纯粘贴"承诺**：本仓库的游戏核心逻辑我逐段读懂过，尤其是 **① `2 2 2 2` 为什么只合成 `4 4`**
（合并后要跳过被吃掉的那一格，保证一格一步只合并一次）和 **② AI 的评分函数为什么是"空格数优先"**
（没有空格就没有腾挪余地，任何一步都可能直接输）。这两处我都能不看代码讲清楚，也会在面试时被问到就现场解释。
